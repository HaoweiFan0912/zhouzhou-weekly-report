# 周周的报 · 保险行业周报

《周周的报》是一份按周发布、面向公众号读者的保险行业新闻周报。每天的新闻已经由自动流程收集进表格，并做了初步分类和打分。你的工作是把这些原始条目变成可以直接发布的内容：选对文章，写好总结和标题，配上插图，排进文档。范围可以是整周，也可以是用户指定的某几天。

## 前置条件

开始前确认下面几项可用。缺哪一项，就先告诉用户缺什么，再尽量完成其余部分：

- **Google Drive / Google Sheets 访问**：通过已配置的 Google Drive 连接器或 MCP 服务器，用来列文件夹、读表格、导出和上传文档。
- **网页读取**：用来读新闻原文，可以是网页抓取工具或浏览器。
- **punk-cover skill**：和本 skill 装在同一个 skills 目录里，用来编译插图 prompt。
- **图像生成工具**：用来按 prompt 出图。没有的话见下文的「缺图处理」。
- **Python 和 python-docx**：用来生成和合并 docx。没有就执行 `pip install python-docx`。

## 数据在哪里

- 根目录（Google Drive）：`<YOUR_DRIVE_FOLDER_ID>`
  https://drive.google.com/drive/folders/<YOUR_DRIVE_FOLDER_ID>
  （安装后把 `<YOUR_DRIVE_FOLDER_ID>` 换成你自己工作目录的文件夹 ID，就是文件夹链接里 `folders/` 后面那一串。没换的话，先问用户要。）
- 根目录下每周一个子文件夹，命名为 `M.D.YYYY-M.D.YYYY`，周一到周日，例如 `11.2.2026-11.8.2026`。先算出目标日期落在哪一周，再在根目录下找到对应文件夹。如果用户要的日期跨了两周，就拆成两份周报，各自写进自己的文件夹。
- 每个周文件夹里有一个 Google Sheet `URL Collection`（工作表 Sheet1），列如下：
  `Importance (1–5)` | `Processing Status` | `URL` | `News Title` | `Publication Date`（YYYY-MM-DD）| `News Category` | `Companies / Organizations` | `Insurance Type` | `Country / Region` | `Summary (2 sentences)` | `Source / Publisher`
- 读取 `Sheet1!A1:K1000`，再按 `Publication Date` 筛出目标日期。这张表由自动流程维护，只读不写，以免干扰它。
- 表格每天 0 点更新前一天的新闻，所以最新只能拿到「昨天」。用户要的日期如果还没有数据，就告诉他哪几天的数据还没到，先写已有的日期。
- 根目录下的 `Templete`、`Preferred Sources`，以及周文件夹里的其他文件，都不是本流程的数据源。

## 选文：哪些文章进哪个栏目

表格的分类标签和周报栏目并不完全一一对应。最大的坑是表格里没有「并购」标签，收购类新闻基本都被标成了「其他」。所以要按内容判断，不能只看标签：

| 周报栏目 | 取哪些行 |
|---|---|
| 保险创新 | `创新产品`，全部 |
| 风险案列 | `风险案例`，全部 |
| 融资 | `融资`，全部 |
| 并购与合作 | `合作`，全部；再加上标成 `其他`、但内容是收购、合并、出售、交割、业务或组合转让的文章，不论重要性 |
| 监管政策 | `政策和监管`，全部 |
| 相关新闻 | 其余 `其他` 中重要性为 4 或 5 的文章，去重后写 |

这样划分的原因：前五个栏目是周报的主体，用户希望这些类别一篇不漏，所以不按重要性筛；「相关新闻」只负责捕捉不属于前五类的重大事件，所以门槛要高，避免淹没主体。

其他细则：
- 同一个 URL 只写一次。前五个栏目里，不同媒体的不同文章各写各的。相关新闻里，同一事件的多篇报道只保留信息最完整的一篇。
- 如果某行明显标错了分类（比如监管新闻标成了「其他」），就放到正确的栏目，并在最后的汇报里列出改动，让用户知道哪些地方偏离了表格。
- 栏目内先按发布日期、再按重要性从高到低排序。

## 写作通则

下面两条适用于总结、公众号标题、图上标题和标签：

- **数字一律用阿拉伯数字，比例一律用百分比**：写「7个县」「16%」「6.5亿加元」，不写「七县」「一成六」「逾半」「近三成」。读者扫一眼就能读懂数字，不用在脑子里换算。
- **写给不一定是业内的人看**：读者对保险感兴趣，但不一定懂行话。行业术语第一次出现时，要么换成通俗说法，要么用半句话解释。

## 每篇文章要做的四件事

### 1. 读原文，写 320 字左右的中文总结
表格里的两句话摘要太薄，写不出有信息量的总结。所以先读原文：抓取失败就换浏览器打开；实在读不到，再退回表格的摘要和标题来写，并在汇报里标出这一篇。

- 长度 320 个汉字左右（300–340 字），一段。这个长度能把来龙去脉和关键数字讲完整，又不至于让公众号读者滑不到底。写完数一下字数，太短就补背景或影响，太长就删次要细节。
- 写清楚：谁、做了什么、关键数字（金额、比例、规模、时间点）、背景或为什么重要。保持客观的新闻口吻，只写原文里有的事实。
- 公司名第一次出现时，有通行中文名就写成「达信（Marsh）」这样，没有就保留英文。金额保留原币种。

### 2. 写一个公众号风格的标题
原标题是写给行业媒体读者的，直译过来在公众号里没人点。所以不用也不直译原标题，而是点出最抓人的信息：一个数字、一个反差、一个影响，或者一个读者关心的问题。

- **先让人看懂，再求吸引人。** 标题要写清楚「谁、做了什么」，用读者熟悉的词。为了压字数，把意思压成行话或自造的缩略说法，是最常见的失败。
- 长度 14–30 个汉字，可以用冒号分成两段。多几个字能讲清楚，就多写几个字。
- 不夸大原文没有的结论，否则会伤周报的可信度。
- 写完自检：假设读者没看正文，只看标题，能复述出发生了什么吗？复述不出来就重写。

| 反例 | 问题 | 改法 |
|---|---|---|
| 香港保险科技商给旧核心加一层，销售与后台共用规则 | 「旧核心」「加一层」是行话，读者不知道说的是什么系统、加了什么 | 香港保险科技公司在老旧核心系统上加一层新系统，让销售和后台用同一套规则 |
| 佛州七县因洪水进入紧急状态，家庭投保率仅约一成六 | 「七县」「一成六」读起来要换算 | 佛州7个县因洪水进入紧急状态，家庭投保率仅约16% |

### 3. 设计插图，用 punk-cover 生成 prompt

插图统一用 punk-cover 的「复古手撕拼贴」风格（style ID：`retro-torn-collage`）：旧报纸、手撕纸边、胶带、邮票、收据、老照片、半调网点和复印颗粒，拼成一张编辑感的新闻海报。整期周报用同一种风格，看起来是一个系列。

设计原则是**直接讲一件事，间接讲背景**：
- **文中最重要的那一条消息，要在图上直接、清楚地展现出来**：大标题加一个主视觉，读者扫一眼就知道发生了什么。
- **背景信息**（谁、在哪、什么时候、为什么、前因后果、影响到谁），用拼贴的贴图和小元素间接交代。读者细看才会发现，但每一张贴图都对应文章里的一条真实信息。

`references/examples/` 里的 9 张参考图是早期的纸雕风格，**风格不再沿用**，只参考它们「用画面讲信息」的思路，比如用地图表示地域、用拆开的票据表示构成。

#### 3a. 提炼核心信息
用一句话写出这篇文章最重要的那一条消息，包含主体、动作和关键数字。例如：「PERILS 公布澳洲东海岸风暴最终行业损失 16.2 亿澳元」。后面所有设计都围绕这句话。

#### 3b. 第一层：直接展现核心信息
这一层要做到「3 秒看懂」。
- **主标题**：把核心信息压缩成 1–2 行，必要时 3 行，每行不超过 10 个字。要让外行看懂，不用行话；数字用阿拉伯数字。标题印在一大块手撕白纸或旧报纸头版的剪切标题条上，黑色或深色粗体，和底色反差大，被其他纸片遮挡的部分不超过一成。
- **关键数字**：如果核心信息里有一个关键数字（金额、比例、数量），它在图上**只出现一次**，从下面两种做法里选一种：
  - 放在标题里，作为标题中被放大、换色的一行，例如「SafePoint拟增 / 巨灾债券保障 / 至少1亿美元」；
  - 从标题里拿出来，单独做成画面里最大或第二大的元素，比如剪报字拼成的大数字、大号印章，或者凭证、支票上的金额。这时标题只写事件，例如标题「澳洲风暴最终定损」，旁边单独放大「16.2亿澳元」。
- **主视觉**：一个能直接代表这件事的主体，用老照片剪片或印刷图片剪片做成，比如被风暴掀翻的屋顶、签约的手和合同、一叠债券凭证、高亮了某个州的地图。它是画面里最完整、最清晰的图像。可以参考下表选画法：

| 核心信息的类型 | 主视觉画法 |
|---|---|
| 构成：一笔钱分几档，一件事有几部分 | 几张撕开或叠放的票据、凭证，每张标上数额 |
| 地域：涉及哪些国家或地区 | 旧地图剪片，用红笔圈出或用胶带高亮相关区域 |
| 进度或状态：已交割、已签约、待批准 | 文件上盖不同的印章：「已交割」「已签约」 |
| 增长或扩张：从 A 到 B | 一排可数的剪纸元素，新增的部分用另一种纸色 |
| 风险或灾害 | 灾害现场的新闻照片剪片，加警示胶带 |
| 交易、合作、融资 | 握手照片剪片、合同、支票，用胶带把双方的元素连在一起 |
| 产品或技术创新 | 产品界面或设备的照片剪片，加手写箭头批注 |

#### 3c. 第二层：用贴图间接交代背景
先从文章里列出 3–6 条背景信息，再把每一条转成一种拼贴素材：

| 背景信息 | 拼贴素材 |
|---|---|
| 地点 | 地图碎片、明信片、邮票、车票或登机牌 |
| 时间、时间线 | 撕下的日历页、日期戳、按顺序贴的票根 |
| 当事公司或机构 | 写着公司名的名片、信封抬头、公文印章（只写名字，不画真实 logo） |
| 金额、交易条款 | 收据、支票、价签、股票或债券凭证 |
| 前因、历史数据 | 旧报纸剪报、老照片、手写的前几次数字（如前三次估损 11.08、15.12、15.01） |
| 受影响的人或物 | 人物、房屋、车辆、店铺的照片剪片 |
| 监管、政策 | 打字机打的条款纸、红色公章、档案夹 |
| 风险类型 | 气象云图、地震波形纸带、警示胶带 |

这些贴图是配角：比主视觉小，分布在四周或主视觉背后，可以互相部分遮挡，颜色和对比都比第一层弱，把视线留给标题和主视觉。

#### 3d. 排版
按编辑设计的惯例来：
- **比例**：16:9 公众号正文配图。punk-cover 这个风格默认 3:4，要在 prompt 里明确写 16:9。
- **视觉层级**：只有一个视觉焦点。第一层（标题、关键数字、主视觉）约占画面的 50–60%，第二层贴图填满其余空间。画面饱满，但主次分明，不是素材乱堆。
- **构图**：标题区放在左侧或左上，约占画面宽度的 40%；主视觉和关键数字放在右侧，视线从标题走到主视觉，形成 Z 字形阅读路线。四边留出约 5% 的安全边距，标题和关键数字不要贴边。
- **同一条信息只出现一次**：标题、关键数字、标签和贴图上的字，彼此不能重复。比如标题已经有「至少1亿美元」，凭证上就不能再印一遍「至少1亿美元」，可以改成只画凭证的花纹，或者印上标题没说的信息，比如「4年期」。重复会浪费画面，还会让读者以为是两件事。贴图要表达的是标题之外的背景。
- **图上可读的文字**：只有主标题、关键数字，和最多 3 个短标签（地名、日期、机构名，或原文里的数字）。报纸剪报上的正文只当作看不清的纹理，不要生成可读的假新闻句子，因为生图模型容易生成乱码或错误信息。所有可读的数字都必须和原文一致。
- **配色**：复古印刷色。旧报纸米黄、黑色油墨、牛皮纸棕做底，加 1–2 个复古强调色突出第一层，比如朱红、芥末黄或蓝绿，按文章氛围选：风险灾害用朱红，融资并购用芥末黄或墨绿，创新科技用蓝绿。整期周报的底色和标题处理保持一致。
- **质感**：真实纸张纤维、撕裂毛边、折痕、胶带的半透明反光、纸片投影、半调网点、复印颗粒和轻微的油墨错位。

#### 3e. 出图前自检
- 只看标题、关键数字和主视觉，3 秒内能说出发生了什么吗？不能，就回到 3b。
- 不看标题，只看贴图，能猜出一些背景吗（在哪、谁、为什么）？每张贴图都能在原文里找到对应的事实吗？至少有 3 张这样的贴图吗？不满足就回到 3c。
- 图上的可读文字是不是只有标题、关键数字和不超过 3 个标签？数字和原文一致吗？
- 把图上所有可读文字列出来，有没有哪条信息出现了两次（同一个数字、同一个地名、同一句话）？有就删掉一处，或者换成新的背景信息。
- 视觉焦点是不是只有一个？贴图有没有抢主视觉？

#### 3f. 交给 punk-cover
打开 punk-cover skill，按它的流程编译 prompt。punk-cover 默认会先追问平台和风格；周报一次有几十篇，逐篇追问会卡住整个流程，所以直接给它下面这些参数：
- 模式：auto（不追问，直接生成）
- 风格：复古手撕拼贴（`retro-torn-collage`）
- 比例：16:9（公众号正文配图）
- 语言：中文
- 主标题：3b 的标题
- 主视觉和关键数字：3b 的设计
- 补充背景：3c 的贴图清单，逐条写明每张贴图是什么、放在哪里、上面写什么字（如果有字）
- 排版和配色：3d 的要求
- 禁用元素：真实公司 logo、可读的假新闻正文、和原文不符的数字、多个抢眼的焦点、重复出现的同一条文字或数字

prompt 按 punk-cover 的规定保存为 `punk-assets/punk-cover/{slug}/prompts/cover.md`。文件开头先写三项，方便事后核对：核心信息一句话；贴图与原文事实的对照表；图上全部可读文字（每条只能出现一次）。

完整示例见 `references/collage-prompt-example.md`。

### 4. 用这个 prompt 出图
- 用可用的图像生成工具出图，保存为 `punk-assets/punk-cover/{slug}/cover.png`。
- **缺图处理**：如果没有图像生成工具，也不要用别的图充数。在插图位置放一行灰色斜体「【插图待生成】」，下面附上完整的 prompt，用户之后可以拿去自己出图。汇报里说明哪些文章还缺图。
- 生成好的图片同时上传到当周文件夹下的 `插图` 子文件夹（没有就新建），文件名用「日期_栏目_短标题.png」，方便用户发公众号时单独取用。

## 排版

文档名为「周周的报」，放在当周文件夹里。栏目顺序和栏目名固定不变：保险创新、风险案列、融资、并购与合作、监管政策、相关新闻。用户会把文档搬进公众号，固定结构能让他不用每周重新调。没有文章的栏目也保留栏目名，下面写「本期暂无」。

```
周周的报                         ← 文档标题（Title）
11.2.2026-11.8.2026              ← 周报时间范围，即当周文件夹名

保险创新                         ← 栏目（Heading 1）
  公众号标题                     ← Heading 2
  插图                           ← 居中，宽度约等于正文宽度
  320 字左右的总结               ← 正文
  来源：媒体名, '原文标题'        ← 小一号字，整句链接到原文 URL
  （空一行，下一篇）
风险案列
融资
并购与合作
监管政策
相关新闻
```

一篇完整条目的示例：

> **澳洲东海岸风暴定损16.2亿澳元：昆士兰独扛94%**
>
> （插图：复古手撕拼贴。左侧手撕白纸上印着标题「澳洲风暴最终定损」，旁边用剪报字单独拼出放大的「16.2亿澳元」；右侧是被掀开屋顶的黑白新闻照片；四周贴着红笔圈出昆士兰的地图碎片和「昆士兰 94%」纸签、「10.26–11.1」日历页、写着前三次估损的手写纸条）
>
> 巨灾数据机构 PERILS 发布了 2025 年 10 月底澳大利亚东海岸强对流风暴的第四次、也是最终的行业损失估计：16.2 亿澳元，比第三次估计高约 8%。……（共 320 字左右）
>
> 来源：Artemis, 'PERILS finalises industry loss estimate for Australia east coast SCS at AU $1.62bn'

## 写入 Google Doc

用户可能已经在文档里手动写了东西，比如「每日一图」，这些不能丢。如果可用的 Drive 工具能直接编辑 Google Doc 正文（插入文字和图片），就直接在对应栏目末尾追加，并跳过已经写过的文章。如果只能新建文件、改文件元数据（常见情况），就用「导出 → 合并 → 重新上传」的方式，并保留旧版作为备份：

1. 在当周文件夹里查找「周周的报」。
2. 如果已存在：把它导出为 docx（导出 MIME 为 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`），放进一个单独的新目录。以来源链接的 URL 为准找出已经写过的文章，这些跳过不重写。
3. 用 python-docx 把新文章插进对应栏目的末尾。已有内容原样保留；缺少的栏目按固定顺序补上。
4. 如果不存在：按上面的结构新建 docx。
5. 把 docx 上传到当周文件夹，转换为 Google Doc，标题设为「周周的报」。
6. 如果原来已有一份，就把旧版改名为「周周的报_备份_YYYYMMDD-HHMM」，不删除。万一合并出错，用户还能从备份里找回。
7. 上传后读一遍新文档，检查栏目是否齐全、每篇是否都有标题、插图（或待生成占位）、总结和来源、有没有重复文章。

## 执行和汇报

- 一周可能有上百条新闻，先列出步骤计划：读表 → 选文分栏 → 按栏目逐篇处理 → 排版上传 → 检查。
- 选完文后，把每个栏目的篇数和标题发给用户看一眼，然后接着做，不用等确认。用户有异议可以随时叫停，而不至于等到最后才发现选错了。
- 最后的汇报简短即可：覆盖的日期、各栏目篇数、文档链接；再列出例外情况：按内容改了栏目的文章、原文没读到的文章、缺图的文章。
- 每次都当作一份新的周报来处理，不沿用其他周的上下文。
