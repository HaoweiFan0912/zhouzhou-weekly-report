# 周周的报 · 保险行业周报

《周周的报》是一份按周发布、面向公众号读者的保险行业新闻周报。每天的新闻已经由自动流程收集进表格，并做了初步分类和打分。你的工作是把这些原始条目变成可以直接发布的内容：选对文章，写好总结和标题，配上插图，排进文档。范围可以是整周，也可以是用户指定的某几天。

## 前置条件

开始前确认下面几项可用。缺哪一项，就先告诉用户缺什么，再尽量完成其余部分：

- **Google Drive / Google Sheets 访问**：通过已配置的 Google Drive 连接器或 MCP 服务器，用来列文件夹、读表格、导出和上传文档。
- **网页读取**：用来读新闻原文，可以是网页抓取工具或浏览器。
- **punk-cover skill**：和本 skill 装在同一个 skills 目录里，用来编译插图 prompt。
- **图像生成工具**：用来按 prompt 出图。没有的话见下文的「缺图处理」。
- **Python 和 python-docx**：用来生成和合并 docx。没有就执行 `pip install python-docx`。

## 数据在哪里

- 根目录（Google Drive）：`<YOUR_DRIVE_FOLDER_ID>`
  https://drive.google.com/drive/folders/<YOUR_DRIVE_FOLDER_ID>
  （安装后把 `<YOUR_DRIVE_FOLDER_ID>` 换成你自己工作目录的文件夹 ID，就是文件夹链接里 `folders/` 后面那一串。没换的话，先问用户要。）
- 根目录下每周一个子文件夹，命名为 `M.D.YYYY-M.D.YYYY`，周一到周日，例如 `11.2.2026-11.8.2026`。先算出目标日期落在哪一周，再在根目录下找到对应文件夹。如果用户要的日期跨了两周，就拆成两份周报，各自写进自己的文件夹。
- 每个周文件夹里有一个 Google Sheet `URL Collection`（工作表 Sheet1），列如下：
  `Importance (1–5)` | `Processing Status` | `URL` | `News Title` | `Publication Date`（YYYY-MM-DD）| `News Category` | `Companies / Organizations` | `Insurance Type` | `Country / Region` | `Summary (2 sentences)` | `Source / Publisher`
- 读取 `Sheet1!A1:K1000`，再按 `Publication Date` 筛出目标日期。这张表由自动流程维护，只读不写，以免干扰它。
- 表格每天 0 点更新前一天的新闻，所以最新只能拿到「昨天」。用户要的日期如果还没有数据，就告诉他哪几天的数据还没到，先写已有的日期。
- 根目录下的 `Templete`、`Preferred Sources`，以及周文件夹里的其他文件，都不是本流程的数据源。

## 选文：哪些文章进哪个栏目

表格的分类标签和周报栏目并不完全一一对应。最大的坑是表格里没有「并购」标签，收购类新闻基本都被标成了「其他」。所以要按内容判断，不能只看标签：

| 周报栏目 | 取哪些行 |
|---|---|
| 保险创新 | `创新产品`，全部 |
| 风险案列 | `风险案例`，全部 |
| 融资 | `融资`，全部 |
| 并购与合作 | `合作`，全部；再加上标成 `其他`、但内容是收购、合并、出售、交割、业务或组合转让的文章，不论重要性 |
| 监管政策 | `政策和监管`，全部 |
| 相关新闻 | 其余 `其他` 中重要性为 4 或 5 的文章，去重后写 |

这样划分的原因：前五个栏目是周报的主体，用户希望这些类别一篇不漏，所以不按重要性筛；「相关新闻」只负责捕捉不属于前五类的重大事件，所以门槛要高，避免淹没主体。

其他细则：
- 同一个 URL 只写一次。前五个栏目里，不同媒体的不同文章各写各的。相关新闻里，同一事件的多篇报道只保留信息最完整的一篇。
- 如果某行明显标错了分类（比如监管新闻标成了「其他」），就放到正确的栏目，并在最后的汇报里列出改动，让用户知道哪些地方偏离了表格。
- 栏目内先按发布日期、再按重要性从高到低排序。

## 每篇文章要做的四件事

### 1. 读原文，写 320 字左右的中文总结
表格里的两句话摘要太薄，写不出有信息量的总结。所以先读原文：抓取失败就换浏览器打开；实在读不到，再退回表格的摘要和标题来写，并在汇报里标出这一篇。

- 长度 320 个汉字左右（300–340 字），一段。这个长度能把来龙去脉和关键数字讲完整，又不至于让公众号读者滑不到底。写完数一下字数，太短就补背景或影响，太长就删次要细节。
- 写清楚：谁、做了什么、关键数字（金额、比例、规模、时间点）、背景或为什么重要。保持客观的新闻口吻，只写原文里有的事实。
- 公司名第一次出现时，有通行中文名就写成「达信（Marsh）」这样，没有就保留英文。金额保留原币种。

### 2. 写一个公众号风格的标题
原标题是写给行业媒体读者的，直译过来在公众号里没人点。所以不用也不直译原标题，而是点出最抓人的信息：一个数字、一个反差、一个影响，或者一个读者关心的问题。
- 12–28 个汉字，可以用冒号分成两段。
- 吸引人，但不夸大原文没有的结论，否则会伤周报的可信度。

### 3. 设计插图，用 punk-cover 生成 prompt
插图要让读者看一眼就知道这篇文章最重要的事。做法是：**标题说「是什么」，画面说「怎么回事」**。画面主体本身要表达文章里的一条真实信息，而不只是装饰。

动手前先看 `references/illustration-examples.md` 和 `references/examples/` 里的参考图，挑两三张和当前文章类型相近的（融资、并购、巨灾、扩张……）。这些是用户认可的样子。

**3a. 确定核心信息。** 用一句话写出这篇文章最重要的事实，包含主体、动作和关键数字。例如「Fairfax 拟发行 6.5 亿加元票据，分两档」。后面的标题、画面和标签都从这句话出发。

**3b. 定图上的标题。** 把核心信息压缩成两行，每行不超过 9 个字，例如「Fairfax拟发 / 6.5亿加元票据」。它不必和第 2 步的公众号标题一样：公众号标题负责吸引点击，图上标题要让人一眼看懂发生了什么。

**3c. 定画面要表达的信息。** 从文章里再挑一条补充信息，用画面主体表达出来。常用画法：

| 补充信息的类型 | 画法 | 参考图 |
|---|---|---|
| 构成：一笔钱分几档，一件事有几部分 | 拆分或叠放的实物，每份标上数额 | 06 |
| 地域：涉及哪些国家或地区 | 地图，高亮相关区域 | 05、07、08 |
| 进度或状态：已交割、已签约、待批准 | 在地图或物件上用不同的道具和标签区分 | 07 |
| 增长或扩张：从 A 到 B | 可数的元素，用颜色区分「已有」和「新增」 | 04 |
| 风险类型：飓风、地震、风暴…… | 画出具体的威胁物，加上抵挡它的盾牌或堤坝 | 03、09 |
| 连接、融资或转化：用 X 支撑 Y，把 X 接进 Y | 用桥把两端连起来 | 01、02 |

画面上最多放一两个标签。标签尽量补充标题没说的信息，比如分档、期限、险种或地区；实在没有可补充的，才重复关键数字。标签和画面里的数字必须和原文一致。

**3d. 出图前自检。** 遮住标题，只看画面，问自己：能看出这篇文章的某个真实信息吗？看不出来，就说明画面只是装饰，回到 3c 换一种画法。

**3e. 交给 punk-cover。** 打开 punk-cover skill，按它的流程编译 prompt。punk-cover 默认会先追问平台和风格；周报一次有几十篇，逐篇追问会卡住整个流程，所以直接给它下面这些参数：
- 模式：auto（不追问，直接生成）
- 比例：16:9（公众号正文配图）
- 语言：中文
- 风格：统一用「立体纸雕概念海报」，整期周报看起来是一个系列。只按文章氛围换配色：米白纸底，加一个主色和最多一个强调色。风险和巨灾用蓝灰，必要时加红或橙强调；增长和扩张用绿；融资和并购用灰配铜色，或用藏蓝；创新和科技用墨绿或雾蓝。
- 标题：3b 的两行标题，放在画面左侧
- 画面主体：3c 的设计，放在画面右侧，写清楚每个物件代表什么、每个标签的文字
- 图上文字：只有标题和标签，不加副标题、正文或说明文字
- prompt 按 punk-cover 的规定保存为 `punk-assets/punk-cover/{slug}/prompts/cover.md`，开头注明核心信息，方便事后核对数字。

### 4. 用这个 prompt 出图
- 用可用的图像生成工具出图，保存为 `punk-assets/punk-cover/{slug}/cover.png`。
- **缺图处理**：如果没有图像生成工具，也不要用别的图充数。在插图位置放一行灰色斜体「【插图待生成】」，下面附上完整的 prompt，用户之后可以拿去自己出图。汇报里说明哪些文章还缺图。
- 生成好的图片同时上传到当周文件夹下的 `插图` 子文件夹（没有就新建），文件名用「日期_栏目_短标题.png」，方便用户发公众号时单独取用。

## 排版

文档名为「周周的报」，放在当周文件夹里。栏目顺序和栏目名固定不变：保险创新、风险案列、融资、并购与合作、监管政策、相关新闻。用户会把文档搬进公众号，固定结构能让他不用每周重新调。没有文章的栏目也保留栏目名，下面写「本期暂无」。

```
周周的报                         ← 文档标题（Title）
11.2.2026-11.8.2026              ← 周报时间范围，即当周文件夹名

保险创新                         ← 栏目（Heading 1）
  公众号标题                     ← Heading 2
  插图                           ← 居中，宽度约等于正文宽度
  320 字左右的总结               ← 正文
  来源：媒体名, '原文标题'        ← 小一号字，整句链接到原文 URL
  （空一行，下一篇）
风险案列
融资
并购与合作
监管政策
相关新闻
```

一篇完整条目的示例：

> **澳洲东海岸风暴定损16.2亿澳元：昆士兰独扛94%**
>
> （插图：左侧标题「澳洲风暴定损 / 16.2亿澳元」；右侧是澳大利亚东海岸纸雕地图，昆士兰被风暴云笼罩、高亮，标签「昆士兰占94%」）
>
> 巨灾数据机构 PERILS 发布了 2025 年 10 月底澳大利亚东海岸强对流风暴的第四次、也是最终的行业损失估计：16.2 亿澳元，比第三次估计高约 8%。……（共 320 字左右）
>
> 来源：Artemis, 'PERILS finalises industry loss estimate for Australia east coast SCS at AU $1.62bn'

## 写入 Google Doc

用户可能已经在文档里手动写了东西，比如「每日一图」，这些不能丢。如果可用的 Drive 工具能直接编辑 Google Doc 正文（插入文字和图片），就直接在对应栏目末尾追加，并跳过已经写过的文章。如果只能新建文件、改文件元数据（常见情况），就用「导出 → 合并 → 重新上传」的方式，并保留旧版作为备份：

1. 在当周文件夹里查找「周周的报」。
2. 如果已存在：把它导出为 docx（导出 MIME 为 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`），放进一个单独的新目录。以来源链接的 URL 为准找出已经写过的文章，这些跳过不重写。
3. 用 python-docx 把新文章插进对应栏目的末尾。已有内容原样保留；缺少的栏目按固定顺序补上。
4. 如果不存在：按上面的结构新建 docx。
5. 把 docx 上传到当周文件夹，转换为 Google Doc，标题设为「周周的报」。
6. 如果原来已有一份，就把旧版改名为「周周的报_备份_YYYYMMDD-HHMM」，不删除。万一合并出错，用户还能从备份里找回。
7. 上传后读一遍新文档，检查栏目是否齐全、每篇是否都有标题、插图（或待生成占位）、总结和来源、有没有重复文章。

## 执行和汇报

- 一周可能有上百条新闻，先列出步骤计划：读表 → 选文分栏 → 按栏目逐篇处理 → 排版上传 → 检查。
- 选完文后，把每个栏目的篇数和标题发给用户看一眼，然后接着做，不用等确认。用户有异议可以随时叫停，而不至于等到最后才发现选错了。
- 最后的汇报简短即可：覆盖的日期、各栏目篇数、文档链接；再列出例外情况：按内容改了栏目的文章、原文没读到的文章、缺图的文章。
- 每次都当作一份新的周报来处理，不沿用其他周的上下文。
